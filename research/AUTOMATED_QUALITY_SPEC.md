# Automated extraction quality gate

11 November 2026. The user declined time-consuming human extraction benchmarks and directed programmatic validation. This supersedes the mandatory human extraction-benchmark workflow for continuing local work. Preserve previous benchmark packets as optional historical artifacts. It does not create human validation, legal review or an empirical accuracy estimate.

Acceptance criteria before implementation:
- Evaluate every in-scope cleaned question and every configured in-scope source body page, including pages without emitted questions. Preserve PDF, cleaned data, accepted metadata and all earlier outputs.
- Structural checks: unique IDs; nonempty stems; MCQ option number/order/labels; valid source/page/bbox/passage references; section-aware duplicate numbers; configured missing/out-of-range numbers. Unknown expectations remain unknown.
- Re-render source pages locally, run an additional Tesseract pass with a different layout mode (PSM 6 at 180 DPI), retain TSV/word coordinates, stderr, software/settings and hashes. This is computationally separate evidence, not a statistically independent truth source. Original OCR pages may share engine errors.
- Compare cleaned text with OCR words from its original question source region. Record ordered lexical token agreement, token counts, missing numeric tokens and negation differences. Match case-insensitively for lexical support; do not call it exact transcription accuracy. Keep source punctuation/numerical legal interpretation outside this support score. Metadata/options cause extra OCR tokens, so do not count every extra source number as an error.
- Run a second, tighter 240-DPI crop OCR pass on questions with low agreement or critical-token discrepancies. Never silently substitute text from OCR; retain disagreements and machine failures in an automatic repair queue.
- Freeze an engineering triage threshold of 98% ordered target-token support plus no critical-token discrepancy. This is not a calibrated 98% accuracy probability. A programmatic gate can pass without humans only if the configured checks pass. Otherwise report NEEDS_AUTOMATED_REPAIR, with exact counts and machine reasons; do not label missing human work as the blocking reason.
- Define synthetic tests that first fail for option/ID defects, preserved negation and numerical mismatches, ordered token agreement, missing OCR evidence, and gate aggregation. Inject known errors into synthetic source strings to test detector sensitivity; keep those results separate from corpus claims.
- Produce source-linked JSON/HTML quality reports and a machine-readable exception queue. No paid API calls or source publication.

Strict-gate refinement, before final corpus sign-off: the 98% threshold is only a triage category. Synthetic testing showed that it can clear a single wrong ordinary word in a long item. The final `strict_support` gate therefore retains every target-token gap as an automatic exception, even when 98% triage support is met. It still measures target-token corroboration rather than exact punctuation, all omitted source content or empirical accuracy. Both initial and tightened synthetic results are retained.
